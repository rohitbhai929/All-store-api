API reference

Endpoints

Replace https://YOUR-RAILWAY-DOMAIN with your deployed Railway public domain.

GET
/health
Public status check; no API key required.
GET
/api/v1/products
Returns available products and their PIDs. Requires X-API-Key.
GET
/api/v1/products/{PID}/plans
Returns plans for a product, including plan_id, duration, remote_duration and prices.
GET
/api/v1/balance
Reads the wallet configured by PUBLIC_API_USER_ID on Railway.
POST
/api/v1/buy
Purchases by plan_id and optionally validates the product PID. Returns order and delivery details.
Wallet model: Purchases use the single Telegram wallet configured through PUBLIC_API_USER_ID. API callers cannot choose arbitrary users. Make sure this account has started the bot and has enough balance.
Quick start

Connect from another service

1. Authentication

Add the API key to server-side requests. Keep it private.

X-API-Key: YOUR_PUBLIC_API_KEY
Content-Type: application/json

2. List products

curl -H "X-API-Key: YOUR_PUBLIC_API_KEY" \
  https://YOUR-RAILWAY-DOMAIN/api/v1/products

3. Submit a purchase

Use the product PID and the plan's numeric plan_id from your API data.

curl -X POST \
  https://YOUR-RAILWAY-DOMAIN/api/v1/buy \
  -H "X-API-Key: YOUR_PUBLIC_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "pid":"YOUR_PRODUCT_PID",
    "plan_id":123,
    "request_id":"ORDER-10001"
  }'

Use a new request_id for every new order. Reuse it only to retry the same order.

Do not put your API key in browser-side HTML/JavaScript or share it in screenshots. For a public website, route purchases through your own protected backend.
